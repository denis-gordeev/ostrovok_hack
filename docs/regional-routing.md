# Казанская агломерация

Включены Казань, аэропорт, Иннополис, Зеленодольск, остров-град Свияжск и
одноимённая железнодорожная станция. Границы: west=48.20, south=55.30,
east=49.85, north=56.35. Общие настройки и версия кэшей — `region_config.py`.

Авто допускает до **150 км по прямой** между точками внутри этой области.
Длина дороги может быть больше; используется граф всей области, чтобы не
обрезать объезды через Волгу. Пеший лимит остаётся 10 км по прямой, длинные
загородные пешие расчёты не выполняются. По умолчанию для загорода агент
сравнивает авто и общественный транспорт и сразу обновляет карту.

Проверка от заданной точки в центре Казани по подготовленному графу:

| Конец автомобильного участка | По прямой | По дороге |
|---|---:|---:|
| Внешняя парковка Свияжска | 28,7 км | 62,5 км |
| Иннополис | 23,2 км | 37,0 км |
| Зеленодольск | 37,7 км | 41,9 км |

Это конкретные проверенные точки, а не универсальные расстояния между любыми
адресами. Смещения от дорожных узлов не включены. Для Свияжска авто строится
до внешней парковки OSM way 941137088; въезд на сам остров запрещён согласно
[сайту музея](https://ostrovgrad.ru/kak-dobratsya-v-sviyazhsk/).

## Карта и кэши

Источник — [выгрузка ПФО Geofabrik](https://download.geofabrik.de/russia/volga-fed-district-latest.osm.pbf).
`complete_ways` сохраняет узлы целых дорог; перед импортом выполняется
`osmium check-refs`. В проверенной вырезке отсутствующих узлов дорог **нет**.
SHA-256 PBF: `988b029124bbf798d3d7900bc80f951cdec295134907d4576f1de3b9a0c4dc09`.
Вариант вырезки из источника Татарстана оказался неполным и не используется.

На VPS: `data/extract/agglomeration-v1.osm.pbf`, база
`data/overpass-agglomeration-v1/`. Старые городские данные сохранены отдельно
для отката. Граф авто: 28 690 узлов, 70 356 направленных рёбер.
HTTP, OSMnx и производные результаты используют пространство
`kazan-agglomeration-v1`; городские кэши не выдаются за расширенные данные.
При следующей замене снимка меняйте `DATA_VERSION` и пересобирайте графы.

## Общественный транспорт

GTFS: **92 маршрута, 1491 остановка, 20 892 рейса**, календарь модели
**27 октября — 25 ноября 2026**. MobilityData Validator 8.0.1 не нашёл ошибок.
OTP 2.10.0 пересобран с расширенной вырезкой, поддерживает BUS/TRAM/SUBWAY/RAIL.

- Bustime: городская сеть и 15 железнодорожных маршрутов с пригодными данными.
  Отправления сохранены; промежуточные и конечные времена модельные.
- 106/108: опубликованные времена обоих концов рейса с
  [сайта Иннополиса](https://innopolis.com/ru/city/bus-schedule), отдельно будни
  и выходные. Промежуточная посадка в этом дополнении не моделируется.
- 407: опубликованные отправления между станцией и островом с
  [сайта музея](https://ostrovgrad.ru/kak-dobratsya-v-sviyazhsk/).
  **Дни курсирования не подтверждены:** ежедневность — допущение прототипа,
  нужно сверять с перевозчиком. Прибытие рассчитывается из дорожной геометрии
  при условных 35 км/ч. Этот участок не считается официальным полным расписанием.

Геометрия дополнительных автобусов построена по дорожному графу и может
отличаться от фактической трассы автобуса. Маски дней проецируются на 30 дней;
праздники, отмены и задержки не учитываются. Покрытие неполное, гарантии
достаточного времени пересадки нет. Речные рейсы не добавлены.

## Повторная сборка

На VPS набор лежит в `data/transit-regional-v1/`; предыдущий — `data/transit/`.
Снимки сайтов, нормализованные расписания, геокодированные остановки с источниками,
модельные геометрии, GTFS, отчёт и `graph.obj` хранятся вне Git.

```sh
uv run python scripts/bustime_to_gtfs.py \
  --source .cache/research/bustime/kazan-city.json \
  --output .cache/transit/regional-base.gtfs.zip --start-date 2026-10-27
uv run python scripts/regional_schedules.py --collect .cache/transit/official-records.json
```

Для объединения нужны проверенные `official-locations.json` и
`official-geometries.json` (текущие версии сохранены на VPS):

```sh
uv run python scripts/regional_schedules.py \
  --base .cache/transit/regional-base.gtfs.zip --output .cache/transit/regional.gtfs.zip \
  --supplement .cache/transit/official-records.json \
  --locations .cache/transit/official-locations.json \
  --geometries .cache/transit/official-geometries.json
```

Неизвестные остановки и отсутствующая геометрия вызывают ошибку, а не заменяются
выдуманными координатами. Для обновлённых остановок сначала проверьте геокодирование.
`scripts/regional_geometries.py` пересчитывает геометрии по сохранённому GraphML.
Затем валидируйте GTFS и собирайте OTP в отдельном каталоге; переключайте
Overpass, OTP и API согласованно. Не заменяйте отчёт без соответствующего графа.

## Проверки на развёрнутом сервере

27.10.2026 проверены HTTP `/drive/route` и `/transit/route` из тестовой точки
в центре Казани до всех трёх направлений. Отправление транспорта — 09:00 +03:00:
Иннополис — автобус 108 (в том числе вариант с городским подвозом),
Зеленодольск — электричка, Свияжск — электричка и 407.
Проверены передача ограничений 407 в ответ API и повторное чтение плана из кэша.
Это результаты расчёта прототипа, не подтверждение фактического движения рейсов.

Полный вызов LangGraph с запросом «Казанский Кремль → остров Свияжск» проверен
в новом диалоге: геокодирование через OSM, `driving_route`, `transit_route`,
два успешных `update_map`, два слоя в состоянии. Длинный `walking_route`
не вызывался. Ответ различает станцию и остров, использует внешнюю парковку
и предупреждает о неподтверждённых днях движения 407. Текст формирует LLM;
географические факты и расписание следует сверять по результатам инструментов.
