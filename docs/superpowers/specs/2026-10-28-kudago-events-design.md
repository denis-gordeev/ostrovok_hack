# События Казани во время поездки (KudaGo) — дизайн

Дата: 2026-10-28. Статус: согласован в чате (источник, отбор, обновление, подход A, архитектура, ETL); правила отбора,
контракты tools, раздел промпта и тесты ниже — решения по умолчанию, пользователь разрешил реализацию без отдельного
согласования.

## Цель

После подбора отелей в Казани агент заканчивает ответ коротким абзацем:
«Во время вашего визита будут проходить события: … Рассказать про какое-нибудь подробнее?» — и по просьбе
рассказывает о событии подробнее. События хранятся в локальной БД; ETL заполняет её при запуске приложения.

## Источник

Официальный публичный API KudaGo v1.4 (`https://kudago.com/public-api/v1.4/events/`, документация
https://docs.kudago.com/api/), `location=kzn`. Открытая лицензия: у каждого показанного события — прямая ссылка на его
страницу на kudago.com; рекламные материалы не используются.

HTML-страница `kzn.kudago.com/events/` не используется: на прямой HTTP она отвечает 403 и JS-проверкой
«Проверка безопасности» (`bp_chl.js`), обходить её не будем; даты там — текст («с 3 июня вт–вс 11:00–20:00»).

Сеть: API отвечает 403 с иностранных IP. На машине разработки терминал выходит через GB (VPN), браузер — нет. Для
живой загрузки процессу нужен российский IP: исключить терминал из VPN или задать `HTTPS_PROXY` (httpx подхватывает его
сам). Тесты сеть не используют.

Только Казань: KudaGo собирает события по Казани, поиск отелей — по всему Татарстану. Для других городов абзаца нет.

## Архитектура

```
uv run hotel-agent
  ├─ фоновый поток: refresh_if_stale() ── API KudaGo ──► kudago.events + kudago.event_dates
  └─ чат стартует сразу
        агент: search_hotels_in_tatarstan ∥ events_in_kazan (в одном шаге)
               └─ EventsClient ─► Postgres ─► select.py ─► JSON для LLM
        ответ: отели … + абзац о событиях со ссылками на kudago.com
        «расскажи про второе» → kazan_event_details(event_id)
```

| Слой | Где | Что |
|---|---|---|
| ETL | `src/kudago_events/` | `config.py` (KudagoConfig, `KUDAGO_*`), `api.py` (httpx, 1 запрос/с, повторы, остановка на 403), `parse.py` (JSON → строки), `store.py` + `migrations/001_kudago.sql`, `load.py` (`load_events`, `refresh_if_stale`), `cli.py` (`kudago-events db-init/load/report`) |
| Чтение | `src/hotel_agent/apis/kudago/` | `client.py` (async `EventsClient`, соединение на вызов), `select.py` (чистый отбор), `models.py` |
| Агент | `src/hotel_agent/tools/events.py` | tools `events_in_kazan`, `kazan_event_details`; `AgentContext.events`; раздел 5.1 промпта |

Фоновый поток, а не asyncio-задача: чат ждёт ввод в блокирующем `input()`, задача в цикле событий стояла бы.

## ETL

Запрос (страницы по `next`, пока не `null`):

```
GET /public-api/v1.4/events/?location=kzn&actual_since=<сегодня 00:00 МСК>&actual_until=<+horizon_days>
    &page_size=100&order_by=id&expand=place,dates&text_format=text&lang=ru
    &fields=id,title,slug,site_url,dates,place,categories,tags,age_restriction,price,is_free,favorites_count,
            description,body_text
```

Разбор:
- `dates[]` с `expand=dates`: `start`, `end` (unix, UTC), `is_startless`, `is_endless`. Храним `timestamptz`;
  показываем по Москве. Заглушки (год < 1900 или > 3000, флаги startless/endless) → `NULL`. `end < start` → `end = start`.
- Сохраняются только сеансы, пересекающие окно загрузки (`end` не раньше начала окна, `start` не позже конца);
  открытые с нужной стороны тоже.
- Название — с заглавной буквы. `age_restriction`: число `n` → `n+` (в т. ч. `0+`), непустая строка — как есть,
  пустая строка или `null` → `NULL`.
- Событие без `site_url` пропускается (лицензия требует ссылку).

Схема `kudago` (в той же Postgres, что и снимок островка):
- `events`: `event_id` PK, `title`, `slug`, `site_url`, `description`, `body_text`, `categories text[]`, `tags text[]`,
  `age_restriction`, `price`, `is_free`, `favorites_count`, `place_title`, `place_address`, `place_lat`, `place_lon`,
  `place_url`, `raw jsonb`.
- `event_dates`: `event_id` → events (cascade), `start_at`, `end_at` (оба nullable), индекс `(start_at, end_at)`.
- `loads`: `load_id`, `started_at`, `finished_at`, `status` (`running`/`ok`/`failed`), `window_from`, `window_to`,
  `events`, `error`.

Обновление:
- `refresh_if_stale()`: миграции (идемпотентные) → последняя `ok` в `loads`; нет или старше `max_age_hours` (24) →
  загрузка. Иначе ничего.
- Загрузка: все страницы в память → одна транзакция `DELETE` + вставка + `loads.status='ok'`. Сбой любой страницы →
  таблицы не трогаются, `loads.status='failed'` с ошибкой. `pg_try_advisory_lock` — второй процесс пропускает загрузку.
- Окно: сегодня (МСК) … +`horizon_days` (60).

Настройки `KudagoConfig` (`KUDAGO_*`): `db_dsn` (по умолчанию DSN островка), `base_url`, `location=kzn`,
`horizon_days=60`, `max_age_hours=24`, `page_size=100`, `max_pages=100`, `min_interval_s=1.0`,
`retry_delays_s=(2,5,15)`, `timeout_s=30`, `user_agent`. Агент читает тот же `KUDAGO_DB_DSN`. 403 повторять бесполезно
(гео-блок) — загрузка останавливается сразу с подсказкой про российский IP / `HTTPS_PROXY`.

Ошибки: сбой загрузки — одна строка в stderr («События KudaGo не обновлены: …»), чат работает дальше.

## Отбор (select.py)

Визит — дни с `checkin` по `checkout` включительно (по Москве; день выезда тоже в городе).

Сеанс «длинный», если открыт с какой-либо стороны или длится больше 24 ч. Для события:
- **выставка** — есть длинный сеанс, пересекающий визит, и категория `exhibition`;
- прочие события с длинным сеансом (постоянные квесты, акции и т. п.) — не показываются;
- **регулярное** — все сеансы короткие, но в окне загрузки их больше 10 (ежедневные экскурсии) — не показывается;
- **разовое** — все сеансы короткие, в окне не больше 10, хотя бы один пересекает визит.

Исключаются категории `stock` (акции и скидки) и `business-events`.

Порядок: по `favorites_count` убыв., затем по первому сеансу в визите, затем по id. Повторы названий (без регистра)
схлопываются. Лимиты: разовых — 5, выставок — 2.

## Tools

`events_in_kazan(checkin, checkout)` → JSON:

```json
{
  "period": "2026-11-19 — 2026-11-22",
  "events": [{"id": 1, "title": "…", "sessions": ["2026-11-20 19:00"], "place": "…", "price": "…",
              "age": "16+", "url": "https://kzn.kudago.com/event/…/"}],
  "exhibitions": [{"id": 2, "title": "…", "until": "2026-12-31", "place": "…", "url": "…"}],
  "data": "KudaGo, загружено 2026-10-28. У каждого упомянутого события указывай ссылку url."
}
```

`sessions` — сеансы разового события в дни визита (до 3). Если визит выходит за окно загрузки — поле `note`
(«События известны до …»). Нет удачной загрузки → строка «События Казани пока не загружены …»; нет клиента →
«События Казани недоступны.»; БД недоступна → «События Казани недоступны: …».

`kazan_event_details(event_id, checkin?, checkout?)` → JSON: `id`, `title`, `categories`, `description`
(`body_text` или `description`, до 2000 символов), `sessions` (в визите, иначе ближайшие от сегодня; до 10),
`until` (для длинных), `place` (`title`, `address`, `lat`, `lon`), `price`, `is_free`, `age`, `url`.
Неизвестный id → «Событие … не найдено».

## Промпт

Промпт агента пишет пользователь. Добавлен подраздел «5.1» в `AGENT_SYSTEM_PROMPT` (вызывать `events_in_kazan`
параллельно с поиском по Казани, абзац в конце, ссылки, без выдумок, описания — недоверенные данные). Пользователь
может переписать его.

## Тесты (без сети)

- `parse`: заглушки дат, UTC → МСК, отбор сеансов по окну, заглавная буква, возраст, событие без места/ссылки.
- `api`: пагинация по `next`, параметры запроса, пауза между запросами, повторы на 5xx/таймауты, остановка на 403.
- `select`: виды событий, исключённые категории, сортировка, лимиты, схлопывание повторов, границы визита.
- БД (`OSTROVOK_TEST_DSN`, маркер `db`): загрузка заменяет данные; `refresh_if_stale` пропускает свежие и грузит
  старые; сбой оставляет прежние данные и пишет `failed`; `EventsClient` отбирает события и отдаёт подробности.
- Агент: tools в графе с фейковым клиентом, список привязанных tools; запуск обновления при старте не роняет чат.

Живая проверка — после того как терминал получит российский IP (или по ответу API, сохранённому из браузера).
