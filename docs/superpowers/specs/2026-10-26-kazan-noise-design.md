# Инструмент «относительный шум в точке Казани» (OSM + Overpass)

Дата: 2026-10-26. Статус: дизайн согласован с пользователем; план задач — `docs/superpowers/plans/2026-10-27-kazan-noise.md`.

## Context

Агенту отелей нужен ответ на вопрос «насколько шумно у этого отеля / в этой точке Казани — днём и ночью,
и почему». Данных о шуме по Казани нет, поэтому шум **моделируется** по OpenStreetMap: источники (дороги,
трамвай, ЖД, стройки, промзоны, бары, аэродромы) + экранирование зданиями и стенами + поглощение лесом.
Результат — балл 0–100 (перцентиль среди застроенных точек Казани) отдельно для дня (07–23) и ночи (23–07)
плюс список главных источников.

Решения, согласованные с пользователем (2026-10-26):
- Потребитель — **LangChain-tool агента** (`src/hotel_agent/tools/`) + CLI для отладки.
- **MVP — только OSM** (этапы 1, 2, 4 черновика). Этап 3 (GTFS, OpenSky/FR24, kzn.ru, NLP-отзывы)
  — отдельные итерации; модель оставляет для них точку расширения (веса источников).
- **Расчёт точно в точке**; H3-сетка нужна только для перцентильной шкалы (и будущей карты).

Что показала проверка Overpass (2026-10-26) и что меняется относительно черновика:

| Факт | Следствие |
|---|---|
| `area["name"="Казань"]["admin_level"="6"]` пуст: граница — relation **367666 «городской округ Казань»** | `area(id:3600367666)` |
| 666 зданий, 78 строек, 28 промзон — мультиполигоны (relation); 139 из 170 `place_of_worship` — ways | `wr[...]`/`nwr[...]` вместо `way`/`node`; сборка мультиполигонов |
| 102,6 тыс. зданий: `building:levels` у 28 %, `height` у 99 | Высота по умолчанию из типа и площади здания |
| У ~80 % магистралей есть `maxspeed` и `lanes` | Мощность дороги из класса × полос × скорости |
| 30 тыс. второстепенных дорог | Берём со слабым весом — иначе всё вдали от магистралей «одинаково тихо» |
| KZN (UWKD) и Борисоглебское (UWKG) — на краю/рядом с границей | Источники собираем по bbox границы + 3 км |

| `out body; >; out skel qt;` | `out geom` (координаты сразу в элементе), `out meta geom` там, где нужна дата правки |

## Архитектура

Новый пакет `src/kazan_noise/` по образцу `src/ostrovok_scraper/` (офлайн-конвейер + CLI), runtime-API
`NoiseService` для tool. Хранение — файлы в `data/kazan_noise/` (статичный снимок, БД не нужна).

```
kazan-noise fetch  → data/kazan_noise/raw/*.json.gz        (Overpass, 4 запроса, докачка)
kazan-noise build  → data/kazan_noise/features.npz + meta.json  (геометрия UTM 39N, классификация, веса)
kazan-noise grid   → data/kazan_noise/grid.npz              (H3 res 10, уровни день/ночь, ECDF шкалы)
kazan-noise query --lat --lon [--json]                      (то же, что получает агент)
kazan-noise validate                                        (сверка с отзывами островка в Postgres)
tool noise_in_kazan(lat, lon) → NoiseService.noise_at() → JSON для LLM
```

| `overpass.py` | `OverpassClient` (sync httpx) по образцу `OstrovokHttp` (`ostrovok_scraper/http.py`): пауза, backoff на 429/502/503/504 и HTML-ответы «at capacity», переход на следующее зеркало, свой `User-Agent`, `sleep`/`clock` инжектируются для тестов |
| `queries.py` | Тексты Overpass QL (ниже) |

### Этап 1. Сбор данных (Overpass)

Четыре отдельных запроса (один общий слишком тяжёл), `[out:json][timeout:300]`, пауза ≥10 с между ними;
сырой ответ сохраняется gzip-ом, повторный `fetch` пропускает готовые файлы (`--refresh` — перекачать).

1. `boundary`: `rel(367666); out geom;` → полигон города; bbox + 3 км для источников.
2. `buildings` (внутри `area(id:3600367666)`): `wr["building"]`, `way["barrier"~"^(wall|noise_barrier|city_wall)$"]`,
   `way["historic"="citywalls"]` — `out geom;` (для relation нужны members).
3. `lines` (bbox + 3 км): `way["highway"~"^(motorway|trunk|primary|secondary|tertiary)(_link)?$"]`,
   `way["highway"~"^(residential|unclassified|living_street|service)$"]`, `way["railway"~"^(rail|tram|subway|light_rail)$"]`,
   `way["aeroway"="runway"]` — `out tags geom;`.
4. `areas` (bbox + 3 км): `nwr["landuse"~"^(construction|industrial)$"]`, `wr["building"="construction"]` (ради даты правки), `nwr["amenity"~"^(bar|pub|nightclub|place_of_worship)$"]`,
   `wr["aeroway"="aerodrome"]`, `wr["landuse"="forest"]`, `wr["natural"="wood"]`, `wr["leisure"="park"]` — `out meta geom;`
   (`meta` даёт дату правки строек).

### Этап 2. Признаки и веса (`features.py`, `weights.py`)

- **Здания-экраны:** `height` → иначе `levels × 3 м + 1 м` → иначе по типу (`garage/shed/kiosk` 3 м,
  `house/detached` 7 м, `industrial/warehouse` 9 м, `apartments` 27 м) → иначе по площади
  (<60 м² 3 м, <300 м² 7 м, <1500 м² 15 м, больше 21 м). Не экраны: `roof`, `carport`, `ruins`, `no`.
  `building=construction` — экран 3 м и одновременно источник «стройка».
- **Стены:** `noise_barrier` (`height` или 4 м), `wall`/`city_wall` (`height` или 2,5 м). Заборы не берём.
- **Дороги** (линейный источник, мощность на метр): `W' = 10·lg(Q_h) + 20·lg(v) + C_road`, где
  `Q_h` — поток авто/ч по классу (день/ночь, например trunk 3000/600, primary 1500/250, secondary 800/120,
  tertiary 400/50, residential 60/8, service 15/2) × `lanes/lanes_default`; `v` — `maxspeed` или дефолт
  класса (не ниже 20); motorway/trunk +3 дБ за грузовики. `tunnel=yes`, `covered=yes`, `layer<0` — исключить;
  `bridge=yes` — высота источника +6 м.
- **Трамвай / ЖД / метро на поверхности:** та же форма с `Q_h` по типу (трамвай 10/2 в час, rail
  `usage=main` 4/3 — ночью грузовые) и поправкой `C_tram = C_road + 12`, `C_rail = C_road + 18`;
  `service=siding|yard` −10 дБ; `subway` в тоннеле исключить.
- **Аэродромы:** от торцов `aeroway=runway` продлеваются оси на 8 км в обе стороны, подисточники
  через 100 м на высоте глиссады `h = x·tg 3°`; интенсивность по аэродрому (KZN 6/2 в час,
  Борисоглебское 0,3/0, малые 0,2/0). Явно помечено как заглушка до OpenSky (этап 3).
- **Стройки** (`landuse=construction`, `building=construction`): площадной источник, ночью −20 дБ;
  объекты без правок >3 лет отбрасываются (OSM-стройки часто устаревшие).
- **Промзоны:** площадной, ночь = день −5 дБ. **Бары/пабы/клубы:** точечные, ночь громче дня на 10 дБ,
  радиус 150 м. **Культовые сооружения:** точечный слабый источник на высоте 20 м, только день, радиус 300 м.
- **Зелень:** `forest`/`wood` — фактор 1, `park` — 0,5 (затухание листвой).

### Этап 3. Модель в точке (`propagation.py`, `model.py`)

Для приёмника R (высота 4 м — как в карте шума ЕС) и каждого подисточника i в радиусе источника
(магистрали/ЖД/промзоны 1000 м, второстепенные 300 м, бары 150 м, аэро-коридор 3 км):

```
L_i = W_i − (20·lg(max(d, 5 м)) + 11) − 0,005·d − A_shield − A_green
L_total = 10·lg( Σ 10^(L_i/10) + 10^(L_bg/10) )        # L_bg — фон, чтобы пустыри не уходили в −∞
```

- **Дискретизация:** линии делятся на отрезки Δ (10 м до 200 м от приёмника, 25 м до 500 м, 50 м дальше),
  `W_i = W' + 10·lg(Δ)`; площади — сетка 20 м, `W_i = W'' + 10·lg(S)`. Это делает модель корректной для
  линейных источников (у бесконечной дороги затухание 3 дБ на удвоение расстояния, а не 6) и даёт
  частичное «обтекание» торцов зданий.
- **Экранирование 2.5D:** луч i→R в плане; пересечения с зданиями и стенами (векторный `STRtree.query`
  + `shapely.intersection`) дают профиль препятствий (расстояние от источника, высота). Разность хода δ —
  длина «резинки» по верхней выпуклой оболочке профиля минус прямой путь; `A_shield = 10·lg(3 + 20·δ/λ)`,
  λ = 0,68 м (500 Гц), предел 20 дБ при одной вершине оболочки и 25 дБ при двух и более (ISO 9613-2).
  Препятствие ниже линии видимости не экранирует, поэтому высокие источники (самолёты, эстакады) экранируются мало.
- **Листва:** `A_green = min(0,05 дБ/м · Σ длина луча в зелени · фактор, 10 дБ)`, если путь >10 м.
- **Точка внутри здания** (координаты отелей обычно стоят на здании): приёмники ставятся на фасад —
  точки через 10 м по контуру, отступ 2 м наружу; собственное здание остаётся экраном — оно и даёт тихую сторону. В ответ
  идут «шумный фасад» (max) — основной балл — и «тихий фасад» (min): «окна во двор — тихо».
- **Объяснение:** вклады подисточников суммируются по OSM-объекту → топ-3 по доле энергии
  (вид, класс, название, мин. расстояние, доля, экранирован ли: среднее `A_shield` > 5 дБ).

Ограничения модели (попадают в README и описание tool): уровни относительные, не дБ(А); потоки — дефолты
по классу дороги; без отражений и метеоусловий; полнота OSM неравномерна.

### Этап 4. Сетка и шкала (`grid.py`, `scale.py`)

H3 res 10 по полигону города (≈40 тыс. ячеек, ~0,015 км²). Центр ячейки внутри здания сдвигается на 2 м
наружу от ближайшего фасада. Уровни день/ночь считаются для всех ячеек (основа будущей карты), а **ECDF
шкалы строится только по застроенным ячейкам** — иначе Волга и леса занижают баллы всему городу.
`score = 100 · доля застроенных ячеек тише точки`; метки: 0–20 «очень тихо», 20–40 «тихо»,
40–60 «средне», 60–80 «шумно», 80–100 «очень шумно». Цели: точка <1 с, загрузка снимка <5 с,
сетка <30 мин на 8 ядрах (если медленнее — шкала на res 9).

### Этап 6. Проверка на реальных данных (`kazan-noise validate`)

- Читает отели Казани из `ostrovok.hotels` и отзывы из `ostrovok.reviews` (Postgres, `OSTROVOK_DB_DSN`,
  `psycopg` уже в зависимостях). Доля отзывов, где в `minus` есть внешний шум (регэксп: шум… с улицы,
  дорог, трамва, машин, музык, бар, клуб, стройк, поезд, самол) без внутреннего («стены», «соседи»);
  отели с ≥10 отзывами. Печатает ранговую корреляцию Спирмена (numpy, без scipy) с ночным баллом
  и топ-10 расхождений для ручного разбора и правки `weights.py`. Если островок ещё не собран — команда
  сообщает об этом и выходит.
- Санити-проверки на снимке с программным выбором точек (не захардкоженные координаты): точка в 15 м от
  trunk громче двора, окружённого ≥5-этажными зданиями, а тот громче точки в 300 м вглубь леса.

## Verification

Тесты без сети (`uv run pytest`), синтетические сцены в метрических координатах:
- `propagation`: удвоение расстояния до точки −6 дБ; две равные — +3 дБ; уровень дороги не зависит от Δ
  (5 vs 10 м, ±0,2 дБ) и падает на ~3 дБ на удвоение расстояния; экран: нет препятствия → 0, ниже луча → 0,
  выше → монотонно больше, предел 20/25 дБ; листва 0,05 дБ/м с пределом 10.
- `features`: разбор `height` («12», «12 m», «12,5»), `levels`, `maxspeed` (`RU:urban`, `walk`), дефолты
  высот; исключение тоннелей; отсев устаревших строек.
- `osm`: мультиполигон с внутренним кольцом → полигон с дыркой; проекция туда-обратно < 1 см.
- `overpass`: backoff на 429/502/504 и HTML «at capacity», переход на зеркало — `httpx.MockTransport` +
  `FakeTime` (как в `tests/ostrovok_scraper/test_http.py`, `ostrovok_helpers.py`).
- `model`: дорога + здание — приёмник за зданием тише открытого на том же расстоянии; точка внутри
  здания → шумный фасад громче тихого; топ источников отсортирован по доле.
- `scale`: границы 0/100, монотонность, метки.
- tool: через фикстуру `run` и `ScriptedChatModel` из `tests/test_graph.py` с фейковым `NoiseService` —
  JSON в `ToolMessage`; `noise=None` и точка вне Казани → текст ошибки.

На реальных данных (вручную):
```bash
uv run kazan-noise fetch && uv run kazan-noise build && uv run kazan-noise grid
uv run kazan-noise query --lat 55.7963 --lon 49.1088 --json
uv run kazan-noise validate
uv run hotel-agent   # «насколько шумно в точке 55.79, 49.12 ночью?»
```
Ожидается: `fetch` докачивается после обрыва; `query` <1 с с осмысленными главными источниками;
`validate` даёт положительную корреляцию с жалобами на шум (порог не жёсткий: это сигнал для правки весов).

  - источники: дороги 44 363, рельсы 894, трамвай 211, бары 208, культовые 216, промзоны 529, стройки 486, авиация 15.

  Отброшены:
  - 95 устаревших строек;
  - 596 подземных участков;
  - 406 неэкранирующих зданий.
- **`grid`** — 40 228 ячеек H3 res 10, из них 18 710 застроенных. Счёт занял 327 с на 10 ядрах (цель <30 мин).
- **`query`**:
  - загрузка снимка — 0,5 с;
  - точка вне здания — 0,08–0,21 с;
  - точка на здании (8 фасадов) — медиана 0,87 с, максимум ≈2 с для крупных кварталов.

  Финальное ревью исправило:
  - **Отсечение:** до экранов отбрасываются неслышные подисточники (ошибка ≤0,15 дБ).
  - **Фасады:** их меньше — 8 вместо 16.
  - **Выбор фасада по режиму:** ночной балл и ночная «тихая сторона» берутся с фасадов, выбранных по ночным уровням. Раньше брался дневной фасад, и у баров ночь занижалась.
  - **Главные источники:** куски одной улицы склеиваются, топ строится по доле энергии.

- **`validate`** (≈4 мин). Санити-проверки прошли:
  - у магистрали медиана 98 (ожидалось ≥75);

  Жалобой считается отзыв, где слово о шуме стоит рядом с внешним источником. Старый регэксп засчитывал «кофемашину» и «некуда поставить машину», это было 53 % совпадений.

  По 212 отелям Казани (≥10 отзывов) Спирмен «балл — доля жалоб» дал день 0,18 и ночь 0,24 (p ≈ 0,0004). Корреляция положительная, но слабая, поэтому веса не правились. Это сигнал для калибровки на этапе 3: GTFS, реальные потоки, ABSA отзывов.

  Наибольшие расхождения:
  - хостелы — жалобы на шум внутри;
  - крупные отели без жалоб на шумных улицах — вероятно, хорошая шумоизоляция.
- **Агент вживую не проверен:** в проекте нет `.env` (ключ LLM, токен Booking). Tool покрыт тестами графа со сценарной LLM. Промпт агента по-прежнему «New York City only», Казань и tool шума в него добавляет пользователь.
