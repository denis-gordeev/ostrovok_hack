# Карта и диалог

VPS: https://188.241.197.121:8443/ui/ — существующий логин и пароль.
Локально:

```sh
npm --prefix web ci
npm --prefix web run build
uv run langgraph dev --config langgraph.json --port 2024 --no-browser --allow-blocking
```

Открыть http://127.0.0.1:2024/ui/. Для разработки интерфейса можно отдельно
запустить `npm --prefix web run dev`: Vite проксирует API на localhost:2024.
Docker собирает интерфейс самостоятельно; Node.js в рабочем контейнере не нужен.

## Подробность шагов

- **Кратко** (по умолчанию): понятные статусы поиска, расчёта и обновления карты.
- **Подробно**: те же действия плюс раскрывающиеся параметры и результаты инструментов.
- **Отладка**: дополнительно события исполнения LangGraph (`debug`). Последние
  150 событий хранятся только в текущей вкладке; длинные значения обрезаются.

Переключение не перезапускает агента: клиент подписывается на `updates`,
`messages-tuple` и `debug` через SSE. Настройка сохраняется в браузере.
Скрытые рассуждения модели не отображаются. Технический режим может содержать
координаты; обычный ответ остаётся понятным. После перезагрузки шаги последнего
запроса восстанавливаются из сообщений инструментов; сырые debug-события — нет.

## Команды карты

Географические инструменты возвращают компактный результат с `data_ref` и
списком `map_variants` для модели. GeoJSON хранится в `ToolMessage.artifact`,
не в тексте для LLM. У транспорта варианты называются `option-1`, `option-2` и т. д.
Агент вызывает `update_map`, например:

```json
{
  "operation": "upsert",
  "layer_id": "parks",
  "title": "Парки поблизости",
  "data_ref": "<data_ref из результата поиска>",
  "variant": "default",
  "kind": "points",
  "color": "#2563eb",
  "show_labels": true,
  "fit_bounds": true
}
```

Операции: `upsert`, `hide`, `show`, `remove`, `clear`, `focus`, `set_labels`.
Подписи включены по умолчанию (`show_labels=true`) и берутся из `properties.name`
проверенного результата. Подписываются точки и центры объектов, но не линии;
без названия подпись не создаётся. Текст смещён от точки и имеет светлую обводку;
пересекающиеся подписи скрываются, при изменении масштаба набор пересчитывается.
`set_labels` с `layer_id` и `show_labels=false/true` выключает/включает подписи
существующего слоя без нового поиска, изменения геометрии или камеры.
Виды: `points`, `geojson`, `cones`. Ссылка должна принадлежать результату
инструмента в этом диалоге. Произвольные координаты в `update_map` не принимаются.
Максимум 20 слоёв; идентификаторы и ссылки текущих слоёв передаются модели.

Слои и камера сохраняются в состоянии LangGraph вместе с диалогом. В браузере
хранится идентификатор последнего диалога. «Новый диалог» начинает отдельный thread.
Флажки и удаление слоёв записываются в состояние. Клик по карте выбирает точку
для следующего запроса («найди рядом с этой точкой»).

Для запроса маршрута по умолчанию рассчитываются пеший и транспортный варианты
и отображаются отдельными слоями. Основной — пеший, только если длина пешего
пути меньше 1 км; от 1 км — общественный транспорт. Если один вариант недоступен,
агент показывает доступный и объясняет ограничение. Явное «только пешком» или
«только на транспорте» имеет приоритет. Для транспорта учитывается ожидание.

## Автомобильные маршруты

Запрос «как доехать на машине» вызывает `driving_route` → `POST /drive/route`
OSMnx API. На карте автомобильный путь оранжевый. Можно попросить сравнить
авто с общественным транспортом и пешим путём — каждый вариант получит свой слой.

Используется направленный граф OSMnx `drive`; маршрут минимизирует оценочное
время по `maxspeed` OSM, а при отсутствии скорости — по предположению для класса
дороги. Графы и результаты сохраняются отдельно от пеших в дисковом кэше.
Точки должны быть внутри вырезки агломерации и не дальше 150 км друг от друга по прямой.
Для авто используется граф всей области: мосты и объезды не обрезаются локальным bbox.
До дорожного узла допускается смещение до 300 м; оно не входит в длину и время.

Это прототип: без пробок, задержек на светофорах, парковки и временных перекрытий.
Односторонние улицы учитываются графом; ограничения отдельных поворотов и
условные ограничения не применяются. Результат не заменяет навигатор.

Доступны Свияжск, Иннополис и Зеленодольск. Для загородного запроса по умолчанию
сравниваются авто и общественный транспорт, без расчёта длинного пешего пути.
[Покрытие и пригородные расписания](regional-routing.md).

## Рельеф и конусы

MapLibre показывает подложку OSM и опциональный рельеф Terrarium из Terrain Tiles /
Mapzen. deck.gl рисует объекты, линии, полигоны и 3D-конусы. Провайдеры тайлов
внешние: Overpass подложку и высоты не создаёт. Тайлы загружаются только для
текущего вида, без массового скачивания, и кэшируются на диске в
`.cache/map-tiles.sqlite` с учётом HTTP Cache-Control (по умолчанию 7 дней).

**Конусы иллюстративные.** `radius_m` и `height_m` задают размер в метрах,
не измеренную высоту и не зону видимости. По умолчанию: радиус 150 м, высота 100 м.
Расчёт видимости с учётом DEM, профили высот и цены/доступность отелей пока
не реализованы. Отели можно искать как обычные объекты OSM (`tourism=hotel`).

## Проверки и развёртывание

### Контекст длинного диалога

Перед каждым вызовом агента узел `remember_results` переносит проверенные
географические артефакты в `geo_results` состояния графа. Они также сохраняются
в `$CACHE_DIR/verified-results/` атомарными JSON-файлами. `data_ref` учитывает
геометрию и исходные метаданные: другой источник или дата не подменяют старый
результат. Координаты WGS84, даты, версии снимков и источники сохраняются точно
как получены; неизвестные даты не дополняются догадками. Чтение результата
не обновляет `retrieved_at`. Точка представления объекта не означает вход.

Узел LangMem `SummarizationNode` готовит сокращённую историю для модели;
полная история чата остаётся в `messages`, накопительное резюме — в `context`.
Порог `CONTEXT_MAX_TOKENS` по умолчанию 16000 приблизительных токенов истории,
бюджет сводки `CONTEXT_SUMMARY_TOKENS` — 1024. Системный промпт, описания
инструментов и служебный перечень ссылок добавляются сверх этого бюджета;
это не жёсткий лимит всего запроса. Суммаризация вызывает ту же LLM без
инструментов и может увеличивать стоимость/задержку в момент срабатывания.

`read_geo_result` восстанавливает точные значения по `data_ref` текущего диалога,
при необходимости по варианту и индексу объекта. `update_map` использует реестр,
поэтому не зависит от наличия старого ответа инструмента в контексте модели.
Реестр сохраняется checkpointer-ом вместе с диалогом; Agent Server управляет им
самостоятельно, для отдельного Python-вызова можно передать `checkpointer`
в `build_agent`. Сам по себе одиночный CLI-запуск не продолжает предыдущий чат.
Сводки не выводятся в пользовательский поток сообщений UI.

### Временные сбои внешних сервисов

Узлы `agent` и `summarize` используют LangGraph `RetryPolicy`: до трёх попыток
всего без пауз между попытками и без jitter. Повторяются сетевые ошибки,
таймауты и HTTP 408/429/500/502/503/504. Ошибки аргументов, авторизации,
сертификатов, пустые результаты и отсутствие маршрута не являются поводом
для повтора. У создаваемого приложением `ChatOpenAI` отключены повторы SDK,
чтобы бюджеты не перемножались. Для явно переданной модели её настройки
повторов остаются ответственностью вызывающего кода.

Прямые read-only POST-запросы Overpass и маршрутов используют тот же бюджет
через `Runnable.with_retry` до преобразования ошибки в ответ инструмента.
Поиск OSMnx получает повторы сетевых исключений; собственная обработка
429/504 и ожидание слота внутри OSMnx сохраняются. Это не общий таймаут запроса:
отдельный HTTP-вызов по-прежнему ограничен `REQUEST_TIMEOUT`.
`ToolNode` целиком не перезапускается: успешные расчёты других способов
проезда и изменения карты не повторяются из-за сбоя отдельного запроса.

### Бюджеты вызовов

`call_usage` в состоянии графа хранит идентификатор последнего сообщения
пользователя, `model_calls`, `tool_calls`, счётчики `by_tool` и `stop_reason`.
Новый пользовательский ход сбрасывает счётчики; продолжение того же хода
и восстановление checkpoint не дают новый бюджет. Разные диалоги независимы.

Положительные целочисленные пределы задаются окружением:

| Переменная | По умолчанию | Что ограничивает |
| --- | --- | --- |
| `AGENT_MAX_MODEL_CALLS` | 12 | Основные обращения агента к модели за ход |
| `AGENT_MAX_TOOL_CALLS` | 48 | Все вызовы инструментов за ход |
| `AGENT_MAX_CALLS_PER_TOOL` | 12 | Вызовы каждого отдельного инструмента за ход |

Бюджет резервируется перед выполнением: повторы `RetryPolicy` и HTTP не
расходуют его повторно. Параллельная группа учитывается по числу вызовов,
включая несколько обращений к одному инструменту; если группа целиком не
помещается в бюджет, ни один её инструмент не запускается. Невыполненные
вызовы получают `ToolMessage` с ошибкой, затем агент завершает ход понятным
сообщением без дополнительной генерации. Полученные данные и карта сохраняются.

Это ограничение логических шагов, не финансовый лимит: суммаризация,
LLM-сводки внутри инструментов Википедии и HTTP-запросы внутри `plan_route`
не являются отдельными основными вызовами агента/инструмента.
Граф задаёт технический `recursion_limit` с запасом относительно бюджета;
UI и CLI используют это значение, чтобы остановка по бюджету происходила
раньше ошибки глубины графа. Внешний API-клиент может переопределить его.

```sh
uv run python -m unittest discover -s tests -v
npm --prefix web test
npm --prefix web run build
```

Развёртывание — существующей командой Compose с тремя файлами. UI подключён через
`http.app` LangGraph и защищён существующим nginx с Basic Auth; новых портов нет.


### Широкий параллельный поиск

Независимые OSM, Wikipedia, веб-поиск и подбор отелей выполняются в одном
пакете tool_calls, до 8 одновременно (`AGENT_MAX_CONCURRENCY`, 1–16).
Реальное распараллеливание зависит от выбранных моделью вызовов; зависимые
координаты и последовательные пересадки не считаются независимыми.
Без дат поездки агент выполняет историческую/маршрутную часть и уточняет даты
для цен отелей, не придумывая их. Wikipedia по умолчанию запрашивается без
`purpose`, чтобы избежать дополнительного LLM-вызова.

`overpass_query`: до 6 попыток (`OVERPASS_MAX_ATTEMPTS`, 1–10) в одном общем
бюджете для HTTP-сбоев, сетевых ошибок и timeout-remark внутри HTTP 200.
Частичные ответы не публикуются и не кэшируются. Ошибки синтаксиса не повторяются.
При исчерпании бюджета инструментов остающийся вызов модели используется для
полезного частичного ответа по уже найденным данным; при полном исчерпании
бюджета модели сохраняется явное сообщение о незавершённости.

`compose_routes` объединяет до 8 проверенных участков по data_ref/variant в
один слой. Неизвестные ссылки, наборы только с точками и разрывы более 750 м
отклоняются. Малые смещения дорожных узлов не являются проверенными подходами.
Это объединение геометрии, а не проверка сквозного расписания: транспортные
этапы с зависимым временем отправления нужно рассчитывать последовательно.

`search_web`: DDGS (Bing/DuckDuckGo), без ключа, до 8 выдержек со ссылками.
Успехи кэшируются в `.cache/web-search/` на 6 часов; срок и таймаут настраиваются
через WEB_SEARCH_CACHE_SECONDS/WEB_SEARCH_TIMEOUT, движки — WEB_SEARCH_BACKEND.
Выдержки не заменяют чтение страниц и подтверждение координат в OSM.

Пустое резюме истории от LLM отклоняется (`context_memory.py`): вместо потери
задачи используется детерминированное сокращение текстов инструментов с
сохранением всех пар вызов–ответ и исходного запроса. Точный запрос дополнительно
передаётся основной модели независимо от сжатия. Артефакты геометрии не меняются.
