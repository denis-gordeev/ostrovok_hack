# Поиск GTFS Казани

Проверено 26 октября 2026. Актуальный публичный GTFS ZIP для Казани (Россия)
не найден. Это результат проверки перечисленных источников, а не доказательство
того, что выгрузки не существует у муниципального оператора.

## Проверенные источники

- Mobility Database: https://github.com/MobilityData/mobility-database-catalogs
  CSV https://files.mobilitydatabase.org/feeds_v2.csv скачан и проверен локально
  (6686 строк). Фида Казани / Татарстана не найдено. Совпадение Kazanlak — Болгария.
  Копия CSV хранится в `.cache/research/gtfs/feeds_v2.csv` и не коммитится.
- Муниципальный каталог «Дороги и транспорт»: https://data.kzn.ru/catalog/3
  В нём пять наборов; публичной ссылки на GTFS в проверенных наборах нет.
- Реестр маршрутов: https://data.kzn.ru/dataset/205
  Указано 80 записей, обновление 16.04.2026. Есть номера, перевозчики, длины
  и текстовые последовательности остановок. В опубликованной схеме нет
  расписания рейсов по остановкам и календаря обслуживания.
- Информация о маршрутной сети: https://data.kzn.ru/dataset/204
  Агрегированная статистика количества маршрутов по годам, не GTFS.
- Графики автобусов: https://kazantransport.ru/buses/184/
  Опубликованы часы работы и интервалы по маршрутам/дням недели;
  это не полный набор отправлений и прибытий по остановкам. Актуальность
  каждого графика отдельно не подтверждена.
- Поиск по GitHub и Transitland не дал подтверждённой ссылки на ZIP Казани.
  Полнота каталогов и поискового индекса не гарантируется.
- Исторический адрес https://bus.kzn.ru/ через веб-инструмент недоступен;
  его работоспособность и наличие GTFS не подтверждены.

## Куда обратиться за исходными данными

Официальный транспортный сайт описывает передачу навигационных данных
АСУ-Т в «Открытую Казань», но не публикует на этой странице GTFS endpoint:
https://kazantransport.ru/opp/137/

МКУ «Организатор пассажирских перевозок»:
https://kazantransport.ru/opp/136/

Контакт портала открытых данных — data.kzn@tatar.ru; на странице просят
указать `opendata` в теме: https://data.kzn.ru/about

Предмет запроса: актуальный GTFS Schedule ZIP для Казани либо машиночитаемые
остановки с координатами, направления/последовательности остановок,
рейсы и времена по остановкам, календарь работы, условия использования
и периодичность обновлений. Отдельно — наличие GTFS Realtime/API.
Сообщения этим организациям не отправлялись.

## Практический вывод

Для подключения к OpenTripPlanner пока не хватает подтверждённого фида.
Собрать GTFS из OSM и интервалов технически возможно только с дополнительными
данными/допущениями: такой результат надо обозначать как модельное расписание,
а не официальный график. Подтверждённой лицензии и срока действия готового
GTFS-фида нет, поскольку сам архив не найден.

## Дополнение: Bustime, 26 октября 2026

По ссылке пользователя https://ru.busti.me/kazan/ найден доступный JSON-дамп
транспортной базы для приложения. Это не стандартный GTFS ZIP.

Прямая ссылка: https://sel.bustm.net/static/other/db/v8/current/10.json
Проверка: HTTP 200, application/json, 4 258 060 байт. Локальная копия:
`.cache/research/bustime/kazan-city.json` (не коммитится).
Формирование дампов описано в исходниках:
https://github.com/norn/bustime/blob/master/utils/turbo_json_dump_update.py
Код имеет MIT-лицензию; условия повторного использования именно базы данных
отдельно не подтверждены. Это не документированное стабильное API.

Проверенная структура:

- `bus`: 140 записей, включая авиацию и пригородные поезда; 87 записей относятся
  к автобусам, троллейбусам, трамваям и метро.
- `nbusstop`: 2160 остановок с координатами.
- `route`: 6772 связи маршрут–остановка с направлением и порядком.
- `routeline`: 245 записей геометрии направлений.
- `trip`: 22 243 записи времени отправления с направлением, маской дней,
  типом и необязательным ID остановки. Это не эквивалент GTFS trips.txt:
  полноценной последовательности stop_times для каждого рейса здесь нет.
- Отправления есть у 132 из 140 маршрутов; среди 87 городских — у 84.
- Только 1341 запись trip имеет явный busstop_id, у остальных он null.
- В дампе не обнаружен отдельный GTFS-календарь с датами действия и исключениями.

На примере автобуса 2 (bus ID 961) извлечены 16/14 остановок по направлениям
и 275 записей отправлений. Пример нормализации сохранён в
`.cache/research/bustime/bus-2-normalized.json`.
В публичной версии исходников schedule_bus выбирает будничные/выходные
отправления и добавляет их только первой остановке каждого направления:
https://github.com/norn/bustime/blob/master/bustime/views.py
Живой сайт использует более новую схему с отдельной таблицей trip, поэтому
исходники помогают понять структуру, но не подтверждают каждый аспект текущего сервера.

Первичный муниципальный источник Казани не установлен. Поля gps_data_provider
в дампе ссылаются на Уфагортранс, а datasource используется многими городами;
это нельзя считать надёжной атрибуцией исходных казанских расписаний.

Практический вывод: сеть и отправления можно технически импортировать одним
файлом. Для точного маршрутизатора по расписанию ещё нужны времена между
остановками/поостановочные расписания и календарь. Если время будет оцениваться
по геометрии/статистике, результат нужно обозначать как модельный.
Массовый обход страниц, опрос GPS и обращение к закрытым API не выполнялись.
